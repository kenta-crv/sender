# 自動架電 改修指示（Cursor用）

使い方: 下の「ステップ1」から順に、**1回に1ステップだけ** Cursor に貼る。
各ステップが終わったら確認方法で動作を見てから次へ進む。
各プロンプトの先頭に「docs/auto_dial_cursor_prompts.md の共通仕様を読んでから作業して」と付ける。

---

## 共通仕様（全ステップ共通・変更しないこと）

### 全体の流れ
1. システムが発信し、受付との会話は AI が判断して、人が吹き込んだ録音を流す（今の双方向ストリーム方式 `lib/bidirectional_call_session.rb` を使う）。
2. 受付が「少々お待ちください」等 → 録音「wait」を流して**保留状態**に入る。
3. 保留明けの第一声は「現在不在です」か「お電話代わりました」のどちらか。
   - 不在 → 録音「担当者不在」を流して切る（全自動）。
   - 代わりました → **担当者本人の声の名乗り録音**「お世話になっております。〇〇の＿＿です」を流し、**流している間に担当者のブラウザ電話をつなぐ**。名乗り終了と同時に担当者と相手を同じ会議通話にする。
4. 転送後、担当者は自分で話してもよいし、画面のボタンで録音を手動再生してもよい。

### 絶対条件
- 名乗り録音の終わりから担当者と話せる状態まで、切れ目を作らない（目標 0.7 秒以内。`CallLatencyLog` で測る）。
- 転送の経路で Twilio の `<Say>`（機械音声）を使わない。今の `DialTransferService::THANKS_TEXT` の読み上げは使わない。
- 名乗り録音が終わった時点から 3 秒以内に担当者が会議通話に入っていなければ、**何も言わずに相手の通話を切る**。担当者側の発信も切る。
- 転送を判定した時点で待機中の担当者がいなければ、同じく何も言わずに切る。

### 待ち時間（初期値。定数にまとめて後から変えられるようにする）
| 状況 | 値 | 動作 |
|---|---|---|
| 話し終わりの判定 | 無音 0.5 秒（今は 0.32 秒） | — |
| 1回の発話の上限 | 8 秒 | 強制的に区切って判定へ（雑音で永久に待つのを防ぐ） |
| こちらが話した後、相手が無言 | 2.5 秒 | 録音「silence_1」（もしもし？） |
| さらに無言 | 2.5 秒 | 録音「silence_2」（お電話が少し遠いようでして…） |
| さらに無言 | 2.5 秒 | 録音「callback」を流して切る |
| 声はするが聞き取れない | すぐ | 1回目 clarify → 2回目 clarify_simple → 3回目 callback で切る |
| 保留中 | 人の返事がないまま 60 秒 | 何も言わずに切る |
| 見張り（保留中以外） | こちらが 10 秒何も流していない | 状態に関係なく上の無言の段階を進める |

### 保留中のルール
- 保留中は、無言でも聞き返さない・「もしもし」を言わない。
- 保留中に聞こえた音声は判定にかけ、結果が transfer / 担当者不在 / フロントアウト / callback のときだけ反応する。それ以外（保留音・雑音・社内の話し声）は**無視し、聞き返し回数にも数えない**。

### 同時発信数（仮決め）
- 同時に発信する件数 = 待機中の担当者の人数（1人なら1件ずつ）。

## ステップ2：文字列ルールの誤判定を直す（AIが2秒以内に返らないときの予備）

```
docs/auto_dial_cursor_prompts.md の共通仕様を読んでから作業して。

verification/front_eval/results.csv の NG 行を直す。対象は app/services/dial_realtime_decider.rb の正規表現と local_nuance の判定順だけ。

特に直すもの:
- 「大変申し訳ございません、少々お待ちください」が担当者不在になる（「ございません」の中の「いません」に一致している）。ABSENT_RE と NEGATION_RE で「ございません」を除外する。
- 「お待たせしました、田中です」「担当の山田と申します」「はい、わたくしですが」が transfer にならない。
- 「出張中」「休み」「戻りません」「打ち合わせ中」「他の電話」「接客中」「外回り」「テレワーク」「直帰」が担当者不在にならない。
- 「けっこうです」（ひらがな）「見送らせて」「おつなぎできない」「取り次ぎはしておりません」がフロントアウトにならない。
- 「夕方以降に」「明日また」「後でかけて」「〜時ごろには戻る」が callback にならない。
- 「どちらの会社」「何のお電話」「営業の電話ですか」「どういう内容」が purpose にならない。
- 「ただいま電話に出ることができません」が着信不在にならない。
- 「おかけになった電話番号は現在使われておりません」は担当者不在ではなく電話不通にする。

迷う場合は「切る分岐」より「待つ・聞き返す分岐」を選ぶ（取り次ぎ中に切る誤判定を最優先でなくす）。

変更してよいファイル: app/services/dial_realtime_decider.rb, verification/front_eval/cases.tsv（行の追加のみ）。
確認: ruby verification/front_eval/run_eval.rb を実行し、変更前後の正解率と、危険な誤判定が0件かを報告して止まる。
```

## ステップ3：待ち時間・保留状態・無音対策

```
docs/auto_dial_cursor_prompts.md の共通仕様を読んでから作業して。共通仕様の「待ち時間」「保留中のルール」をそのまま実装する。

やること:
1. lib/utterance_vad.rb: HANGOVER_MS を 500 に。発話が 8 秒続いたら強制的に終了扱いにする。
2. lib/bidirectional_call_session.rb:
   - LISTEN_TIMEOUT_SEC（8秒）をやめ、共通仕様の 2.5 秒×3段階に置き換える。
   - 判定が wait になったら保留状態に入る。保留中は無言タイマーを 60 秒にし、60 秒たったら何も流さずに切る。保留中は transfer / 担当者不在 / フロントアウト / callback 以外の判定を無視し、unknown_streak も増やさない。
   - 見張り: 保留中以外で、こちらが 10 秒何も流していなければ無言の段階を1つ進める。
   - 再生する録音が見つからない（audio_cache_miss）とき、何もせず聞く状態に戻すのをやめ、clarify → callback の順で代わりを流す。どれもなければ切る。
3. 録音キー silence_1（もしもし？）と silence_2（お電話が少し遠いようでして…）を追加し、既存の録音登録画面から登録できるようにする（既存の clarify 系と同じ登録方法に合わせる）。
4. 接続直後の挨拶: 今、相手の第一声を待たずに挨拶を流していないか確認して報告する。待っていない場合は、相手の第一声の終わり（または無音 1.5 秒）を待ってから挨拶する形にする。

各イベント（保留開始・保留終了・無言の段階・強制区切り）を CallLatencyLog に記録する。
変更してよいファイル: lib/utterance_vad.rb, lib/bidirectional_call_session.rb, app/services/dial_flow_engine.rb, app/models/dial_script.rb と、録音登録に必要な最小限のファイル（触る前にファイル名を報告して承認を取る）。
確認: DialFlowSimulator かテスト通話で、無言・保留・雑音の3パターンの動きを報告して止まる。
```

## ステップ4：担当者のブラウザ電話（待機画面）

```
docs/auto_dial_cursor_prompts.md の共通仕様を読んでから作業して。

担当者がブラウザで待機し、着信を自動で受ける画面を作る。

やること:
1. Twilio Voice JavaScript SDK（バージョンは固定で指定）を使った待機画面を1ページ新規作成する。ログインは既存の管理者ログインを使う。
2. アクセストークンを返すエンドポイントを作る（Twilio::JWT::AccessToken + VoiceGrant、incoming_allow: true、identity は担当者ごとに一意）。必要な環境変数は .env.sample に名前だけ追記する（TWILIO_API_KEY_SID, TWILIO_API_KEY_SECRET, TWILIO_TWIML_APP_SID）。
3. 画面の状態は「待機中」「通話中」「離席」の3つ。待機中に着信したら、**呼び出し音を鳴らさず自動で応答**する。
4. 待機中の担当者をサーバー側で把握する（15秒ごとの生存通知、30秒途絶えたら離席扱い。Redis に保存）。
5. 通話中は、相手との会話の文字起こし（既存の CallTranscriptBroadcaster）と会社名を画面に出す。
6. 同時発信数を「待機中の担当者数」までに制限する（app/jobs/auto_dial_batch_job.rb）。

既存の画面のレイアウトには合わせなくてよい。既存ページは一切変更しない。
確認: ブラウザで待機 → テスト用に client:<identity> へ発信して自動応答されることを報告して止まる。
```

## ステップ5：転送フロー（名乗り録音の間につなぐ）

```
docs/auto_dial_cursor_prompts.md の共通仕様を読んでから作業して。共通仕様の「全体の流れ」3番と「絶対条件」を実装する。

やること:
1. 判定が transfer になった瞬間に、同時に次の2つを始める:
   a. 待機中の担当者を1人選んで通話中にし、client:<identity> へ発信して会議通話に入れる（DialTransferService.start_operator! を電話番号ではなくブラウザ宛てに変更）。
   b. 双方向ストリームで、その担当者の名乗り録音（録音キー intro、担当者ごとに登録）を流す。
2. 名乗り録音が終わったら、相手の通話を同じ会議通話へ移す（今の redirect_handoff の transfer 経路。<Say> は使わない）。
3. 名乗り終了から 3 秒以内に担当者が会議通話に入っていなければ、何も流さずに相手の通話を切り、担当者側も切る。結果は「担当者不在」で保存し、ログに transfer_failed を残す。
4. 転送判定の時点で待機中の担当者がいなければ、何も流さずに切る。
5. CallLatencyLog に intro_start / intro_end / operator_joined / customer_joined を記録し、intro_end → customer_joined の秒数を出す。
6. 担当者ごとの名乗り録音を登録できるようにする（ステップ4の待機画面に録音アップロード欄を追加でよい）。

変更してよいファイル: app/services/dial_transfer_service.rb, app/services/twiml_builder.rb, app/controllers/twilio/voice_controller.rb, lib/bidirectional_call_session.rb, lib/call_redirector.rb, ステップ4で作ったファイル。他は触る前に報告。
確認: テスト通話で「代わりました」と言い、名乗り終了から担当者の声までの秒数を報告して止まる。0.7 秒を超える場合は原因と改善案を報告する（勝手に方式を変えない）。
```
